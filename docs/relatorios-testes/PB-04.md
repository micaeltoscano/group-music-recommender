criados atomicamente (mesmo `commit`, relação em cascata); resposta tipada expõe apenas campos
públicos.

## Casos planejados executados

### CT-PB04-01 — Criação por usuário autenticado
- Status: **Aprovado**
- Evidência: `POST /rooms` autenticado (servidor real + Postgres) → **201** com `code` `M82A-MA4J`,
  `status=open`, membro host; `db.query(MusicSession).count()==1` e membro persistido `(user_id=1,
  role=host)`. Teste automatizado `test_ct_pb04_01_...` verde.

### CT-PB04-02 — Criação sem autenticação é bloqueada
- Status: **Aprovado**
- Evidência: `POST /rooms` sem cookie → **401**; com cookie inválido (`vibe_session=lixo`) → **401**;
  nenhuma sala criada (`count()==0` no teste). Cobre sessão ausente **e** inválida.

### CT-PB04-03 — Código curto único
- Status: **Aprovado**
- Evidência: **20 criações concorrentes** (`ThreadPoolExecutor`, 8 workers) contra **Postgres real**
  → 20 códigos distintos. Teste unitário adicional cobre 12 criações paralelas em SQLite e o caminho
  de colisão forçada (`_generate_room_code` monkeypatched: `ABCD-EFGH`,`ABCD-EFGH`,`JKLM-NPQR` →
  retry sem estado parcial). `UNIQUE(code)` confirmado no catálogo (`music_sessions_code_key`).

### CT-PB04-04 — Host é o primeiro integrante e tem papel host
- Status: **Aprovado**
- Evidência: após criação, exatamente **1** membro com `role=host` e `user_id == host_user_id`;
  varredura em todas as 21 salas do banco: **nenhuma** com vínculo host inconsistente.

### CT-PB04-05 — Expiração de 24h
- Status: **Aprovado**
- Evidência: resposta real `created_at=2026-07-14T20:24:53Z`, `expires_at=2026-07-15T20:24:53Z` →
  diferença **exata de 24h**; teste confirma `expires_at - created_at == timedelta(hours=24)` no
  payload e na persistência.

### CT-PB04-06 — Retorno da API não expõe dados sensíveis
- Status: **Aprovado**
- Evidência: corpo contém apenas `{id, code, status, created_at, expires_at, members}` e cada membro
  apenas `{user_id, display_name, image_url, role, joined_at}`; texto serializado **não** contém
  `token`, `session` nem dados de terceiros (`private outsider`).

## Testes adicionais (adversariais)

- **Servidor real vs Postgres** (não só TestClient/SQLite): 401 não-autenticado e 201 autenticado
  reproduzidos ponta a ponta.
- **Concorrência real** no Postgres (20 execuções) — unicidade garantida pela restrição do banco.
- **Migração `0003_pb04_rooms` ida/volta/ida** no Postgres: `upgrade` cria `music_sessions` +
  `music_session_members` (com `UNIQUE(code)` e PK composta `session_id,user_id`); `downgrade`
  remove ambas (`has_table` → False); `upgrade` recria. Sem erro.
- **Regressão:** suíte completa **27 passed / 0 failed** (PB-01, PB-02, PB-04); build Vite OK.
- **Scope creep:** `Home.jsx` só cria a sala e exibe o código — sem join/lobby/polling (PB-05).
