# Relatório de QA — PB-14 (Correspondência das músicas no Spotify)

## 1. O que foi testado

Validação do motor de correspondência (track matching) responsável por normalizar nomes e artistas das candidatas, buscar no Spotify, calcular a similaridade, garantir que a música esteja disponível no mercado do host e persistir o resultado na tabela `playlist_run_tracks`.

Os testes (`test_pb14_track_matching_qa.py` e `test_pb14_track_matcher.py`) garantem que o sistema consegue descartar candidatas ambíguas ou falsos positivos e selecionar o melhor ID Spotify disponível para a faixa gerada, validando todos os cenários estressantes do Backlog do Produto (§10).

## 2. Cenários Adversariais Testados

1. **CT-PB14-01 — Correspondência bem sucedida**
   - **Condição:** API do Spotify retorna faixa homônima com `is_playable=True` e `name` + `artist` correspondentes.
   - **Resultado:** A similaridade passa do limiar de confiança, status = `matched` e ID Spotify salvo no banco. Aprovado.

2. **CT-PB14-02 — Correspondência falha por baixa confiança**
   - **Condição:** Busca retorna lixo não relacionado ou um cover diferente do artista desejado.
   - **Resultado:** Similaridade < 0.8. A música cai em estado `discarded` com motivo devidamente logado. Aprovado.

3. **CT-PB14-03 — Música indisponível no mercado do host**
   - **Condição:** API do Spotify marca `is_playable=False` para o mercado especificado pelo host.
   - **Resultado:** O item é ignorado e nenhum outro correspondente passa. O status fica como `discarded`. Aprovado.

4. **CT-PB14-04 — Tratamento de API fora do ar (vazia ou exceção)**
   - **Condição:** Rate limit, erro HTTP 500, ou payload não-lista de resposta.
   - **Resultado:** O código intercepta o erro e marca como `discarded`, evitando que a geração da sala paralise inteiramente. Aprovado.

5. **CT-PB14-05 — Normalização de Strings**
   - **Condição:** Entradas de candidatos com strings sujas como `Track [2021 Remaster]`, `Song (Live)`, `Song - Remastered 2011`.
   - **Resultado:** A função pura do motor limpa parênteses, colchetes e sufixos após hífens. Aprovado nos testes unitários.

## 3. Avaliação de Qualidade (Definition of Done)

- **Testes unitários/integração:** Escritos e passando.
- **Motor puro:** O motor em si (cálculo de similaridade) não contém I/O de rede ou estado.
- **Segredos:** Nenhum exposto ou vazado.
- **Resiliência:** Tratamento robusto e explícito (try/except) sobre a API do Spotify. O matching descarta, mas não quebra o loop geral.

## 4. Conclusão

**Status:** VALIDADO. O PB-14 implementou corretamente a lógica de verificação e consolidação do ID canônico do Spotify usando o token do Host. O motor está pronto para a próxima etapa (PB-15: Criação Real da Playlist).
