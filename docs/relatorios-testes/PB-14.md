## Casos planejados executados

### CT-PB14-01 — Correspondência bem sucedida
- Status: **Aprovado**
- Comando: `pytest tests/test_pb14_track_matching_qa.py::test_pb14_successful_matching`
- Resultado observado: A similaridade passa do limiar de confiança, status = `matched` e ID Spotify correto (spotify_123) salvo no banco.
- Evidência: Teste unitário passando de forma transacional.

### CT-PB14-02 — Correspondência falha por baixa confiança
- Status: **Aprovado**
- Comando: `pytest tests/test_pb14_track_matching_qa.py::test_pb14_below_confidence`
- Resultado observado: Quando a busca retorna lixo ou diferente (similaridade < 0.8), a música cai em estado `discarded` com o motivo de baixa confiança.
- Evidência: O descarte não para o loop de geração; as faixas ruins não poluem o resultado.

### CT-PB14-03 — Música indisponível no mercado do host
- Status: **Aprovado**
- Comando: `pytest tests/test_pb14_track_matching_qa.py::test_pb14_unplayable_market`
- Resultado observado: Quando a faixa está `is_playable=False`, ela é pulada. Se nada sobrar, salva como `discarded`.
- Evidência: Teste mock confirmando a inserção da trilha com motivo apropriado.

### CT-PB14-04 — API fora do ar (Rate Limit / Exceções)
- Status: **Aprovado**
- Comando: `pytest tests/test_pb14_track_matching_qa.py::test_pb14_empty_results_or_error`
- Resultado observado: O código intercepta o erro e marca como `discarded`, informando o erro, sem estourar o backend inteiro.
- Evidência: Teste de exceção confirmando o log no banco em `discard_reason`.

## Testes adicionais executados
