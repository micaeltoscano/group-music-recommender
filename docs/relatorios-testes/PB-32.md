## DEF-PB32-01 — Lock de sincronização falha entre event loops e workers

- Severidade: **Alta**
- Caso relacionado: CT-PB32-05
- Pré-condições: lock do mesmo `user_id` exercido em um event loop anterior; nova concorrência usa
  sessões independentes.
- Passos: executar a suíte focada acima.
- Esperado: uma biblioteca final, sem exceção, duplicidade ou erro 500.
- Observado: `RuntimeError: <asyncio.locks.Lock ...> is bound to a different event loop`.
- Evidência: `backend/tests/test_pb32_library_sync_qa.py::test_qa_concorrencia_com_sessoes_independentes_converge`.
- Módulo relacionado: `backend/app/services/library_sync_service.py`, dicionário `_USER_LOCKS`.
- Impacto: o fluxo pode falhar em concorrência; locks em memória também não coordenam processos ou
  workers distintos, contrariando o lock/upsert por usuário previsto.
- Recomendação: adotar coordenação vinculada ao banco/transação (adequada a PostgreSQL) e evitar
  armazenar locks associados permanentemente a event loops; validar com sessões independentes.
- Status: **Aberto**
